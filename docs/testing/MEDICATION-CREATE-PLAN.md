# Medication create UI plan

Base a137b58. SRS-PHARMACY FR6.1 requires pharmacist adding medications. Existing POST /medications permits pharmacist/Admin, validates name>=2, unit string, currentStock integer0..2147483647, optional reorderThreshold same bounds. Server defaults omitted threshold to10. Current UI cannot create medications. No API, role, schema, dependency, matching or medication-edit policy change.

Wireframe: Pharmacy heading, new Create medication card, existing stock adjustment card, pending prescriptions. Full-width name/unit, current stock and optional reorder threshold, helper explaining existing default10, submit and success/error states. Exact strings preserved, no clinical interpretation or name normalization. Use existing MUI spacing/palette/typography, keyboard form submission, Arabic RTL/English LTR. Created selection shared with stock form; existing dispense list refreshes through same medications query.

Safety: medication-create-only sessionStorage marker keyed to authenticated user, synchronous before POST; unavailable storage blocks sending. Current confirmed response<500 clears, stale/network/timeout/cancel/5xx retains. Pending disables inputs. Unknown hold persists across reload/logout/return in same tab; explicit successful list readback and acknowledgment discards draft. No automatic retry, no server idempotency, no proof delayed request is terminal, no cross-tab hold or universal other-write guarantee. Do not persist draft or credentials. Query result insertion avoided; current reads invalidated only.

Tests: pure payload/zero/optional/default/boundaries and marker; actualPG17/18 isolated fictional create/list/adjust/dispense,401/six403/validation/auditrollback, committed-response-loss/reload/logout/no repost, admin UI, old-session response/cache, EN1280/AR390 pixels. Independent source/security review before exact commit/CI and hosted fake-data smoke, private changed/new exports. FullHMS remains incomplete.
