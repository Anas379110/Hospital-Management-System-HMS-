# UI-UX.md — نظام إدارة المشافي (HMS)

## 1. Personas (مرجع من PROJECT.md)
موظف استقبال، طبيب، ممرض/ة، صيدلي (لاحقاً)، مدير مشفى — كل دور له لوحة تحكم (Dashboard) مختلفة حسب الصلاحيات.

## 2. User Flows الأساسية (MVP)

### Flow 1: تسجيل مريض جديد وحجز موعد (موظف استقبال)
تسجيل دخول → لوحة الاستقبال → "مريض جديد" → تعبئة البيانات → حفظ (يظهر MRN) → "حجز موعد" → اختيار قسم/طبيب/وقت متاح → تأكيد.

### Flow 2: مراجعة طبيب لمريض (طبيب)
تسجيل دخول → جدول مواعيد اليوم → اختيار مريض → عرض السجل الطبي السابق → تسجيل زيارة جديدة (تشخيص + وصفة) → حفظ.

### Flow 3: تسكين مريض (ممرض/ة)
تسجيل دخول → البحث عن مريض → اختيار القسم → عرض الأسرّة المتاحة فقط → تأكيد التسكين.

### Flow 4: متابعة إدارية (مدير مشفى)
تسجيل دخول → لوحة إحصائية عامة (إشغال الأسرّة لكل قسم، عدد المواعيد اليوم) — قراءة فقط، لا تعديل بيانات سريرية.

## 3. Screens (نطاق MVP)
1. شاشة تسجيل الدخول
2. لوحة تحكم رئيسية (تختلف محتوياتها حسب الدور)
3. قائمة/بحث المرضى
4. ملف مريض (بيانات + سجل طبي + المواعيد)
5. نموذج تسجيل مريض جديد
6. تقويم/جدول المواعيد
7. نموذج حجز موعد
8. شاشة الزيارة الطبية (تشخيص + وصفة)
9. خريطة الأقسام والأسرّة (Grid بصري لحالة كل سرير)
10. نموذج التسكين/الخروج
11. لوحة إحصائية للمدير

## 4. Navigation (حسب الدور)
- **Receptionist:** مرضى، مواعيد
- **Doctor:** مواعيدي، مرضاي، (بحث عام محدود)
- **Nurse:** الأقسام والأسرّة، بحث مرضى
- **Admin:** كل الأقسام + إدارة المستخدمين
- **Manager:** لوحة إحصائية فقط (Read-only)

القائمة الجانبية تتغيّر ديناميكياً حسب `role` — لا تُعرض روابط لا يملك المستخدم صلاحية الوصول إليها أصلاً (لا الاعتماد على الحجب من طرف API فقط).

## 5. Wireframes → Mockups → Prototype
- **Wireframe (Low-Fi):** يُرسم يدوياً/بأداة بسيطة (مثل Excalidraw) قبل أي كود — يُوثَّق في مجلد `docs/design/wireframes/` أثناء Development الفعلي (لا يُنشأ الآن ضمن التخطيط النصي).
- **Mockup (High-Fi):** Figma، باستخدام Design System أدناه.
- **Prototype:** نموذج Figma تفاعلي يُعرض على عيّنة من الطاقم الطبي الفعلي للحصول على تغذية راجعة **قبل** بدء التطوير الفعلي — خطوة إلزامية حسب الدليل الأساسي.

## 6. Design System (أساسيات — يُفصَّل لاحقاً في Figma)
- **Typography:** خط يدعم العربية بوضوح (مثل Cairo أو Tajawal للعربية، مع Inter/Roboto للإنجليزي) — حجم أساسي 16px لقراءة مريحة في بيئة عمل سريرية.
- **الألوان:** تباين عالٍ (نسبة تباين ≥ 4.5:1 — معيار WCAG AA)، ألوان دلالية واضحة: أخضر=متاح، أحمر=مشغول/خطر، أصفر=تنبيه/صيانة.
- **مكتبة UI:** MUI (راجع TECH-STACK.md) — يوفر مكونات جاهزة تدعم RTL/LTR رسمياً.

## 7. Loading / Empty / Error States
- **Loading:** مؤشرات تحميل واضحة (Skeleton أو Spinner) لكل طلب API — لا شاشة فارغة صامتة.
- **Empty State:** رسالة بشرية واضحة (مثال: "لا توجد مواعيد اليوم" بدل جدول فارغ بلا تفسير).
- **Error State:** رسائل خطأ بلغة بشرية عربية واضحة (مطابقة لصيغة API الموحدة في `API.md`) — **لا تُعرض Stack Trace للمستخدم أبداً** (متطلب NFR صريح).

## 8. Accessibility
- معيار **WCAG 2.1 Level AA** كحد أدنى.
- Alt text لكل الأيقونات ذات الدلالة الوظيفية.
- كل عناصر التحكم قابلة للوصول عبر لوحة المفاتيح (مهم في بيئة سريرية سريعة الحركة).

## 9. Responsive Design
- **Desktop-first** (وليس Mobile-first) — بيئة العمل الأساسية هي محطات عمل ثابتة في المشفى (استقبال، محطات تمريض).
- دعم Tablet كأولوية ثانية (جولات الأطباء المحتملة بأجهزة لوحية) — بلا التزام بدعم شاشات هاتف صغيرة في MVP (خارج النطاق — `SCOPE.md`).

## 10. Localization & RTL
- عربي هو اللغة الافتراضية (RTL كامل: اتجاه النص، محاذاة العناصر، انعكاس الأيقونات الاتجاهية كالأسهم).
- إنجليزي كخيار ثانوي (LTR) — تبديل فوري عبر إعداد مستخدم، بلا حاجة لإعادة تسجيل الدخول.
- كل النصوص عبر مفاتيح `i18next` — **ممنوع نص مكتوب مباشرة (Hardcoded) في الكود** (قاعدة صارمة من `CLAUDE.md`/`AGENTS.md` لاحقاً).
