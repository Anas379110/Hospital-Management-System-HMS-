3. Verify actual socket peer and forwarding headers without durable visitor/IP logging. Do not trust arbitrary X-Forwarded-For, a hop-count guess or outbound IP ranges. Inject forged chains and require rate limiting to remain on a stable trusted identity; test two independent clients are not collapsed into a single key. 4. Axios has no configured timeout and no automatic mutation retry. The qualification client now labels missing-response writes as unknown, tells the user not to retry before checking records/audit, and holds demo billing writes in the same tab across reload/role changes until explicit reconciliation acknowledgement. This is a user acknowledgement, not automatic proof that reconciliation occurred. Bilingual real-browser mocked network tests verify pending double-submit prevention, busy response, unknown-result hold and no auto-retry. Other pages receive the unknown-write warning but do not have the billing hold. This avoids a short client timer that falsely labels an in-flight mutation as failed, but is not acceptable proof of bounded UX. Measure browser-visible request times and pending-button state through the actual proxy with mixed invoices/items and another real mutation. Check 503/Retry-After, expiry, isolation, DB commit counts and audit counts after pressure. Do not retry mutations automatically. Network interruption can leave a mutation outcome unknown; inspect its resulting record before resubmitting.
5. Test client disconnect during queued and active writes. Capacity stays held until DB work settles, not response close. Confirm counts afterwards. The24pending-transaction and24handler limits are per instance, not cluster capacity. A successful36request test created12invoices and returned24bounded503, not a24write capacity promise.
6. Record actual end-to-end bounds. maxWait30seconds plus execution10seconds are transaction limits, not an HTTP deadline, because guard and domain transactions are sequential. Avoid adding a timer that sends503 while a commit can still finish. If a UX bound requires cancellation, it must cancel or reconcile the transaction, not just abandon the response. Do not close this gate using only direct-ORM or local HTTP numbers.

## Controlled test endpoint

For qualification only set HMS_QUALIFICATION_MODE=true and an independent HMS_QUALIFICATION_SECRET of at least32characters. Without it startup fails. Every request requires X-HMS-Qualification with the exact secret, except exact GET /api/v1/health. Browser tests send it as a header on all requests, never a query string. Test forged forwarded headers with the correct qualification header so the edge test reaches application guards. The gate also protects assets and bootstrap. It is not production auth and does not prove the final ungated configuration. Record the qualification instance for later explicit cleanup; do not silently delete it or rotate shared credentials. No visitor-facing release until its independent gates pass.
