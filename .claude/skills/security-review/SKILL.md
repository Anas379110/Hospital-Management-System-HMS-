# مراجعة أمنية إلزامية — HMS

## متى تُستدعى
قبل إغلاق أي Feature تلمس: بيانات مريض، مصادقة، صلاحيات، أو أي عملية Create/Update/Delete حساسة.

## Preconditions
الكود والاختبارات الوظيفية مكتملة بالفعل — هذه مراجعة إضافية لا بديلة.

## خطوات التنفيذ
1. اسأل: "افترض أنك مهاجم متمرس — كيف تستغل هذا الكود تحديداً؟"
2. تحقق من:
   - هل كل Input يمر عبر DTO+class-validator؟ (لا ثقة بمدخلات العميل)
   - هل RBAC Guard مطبَّق فعلياً على هذا الـ Endpoint بالضبط (لا نسيان)؟
   - هل توجد إمكانية SQL Injection؟ (Prisma يحمي افتراضياً — تحقق من عدم استخدام Raw Query غير آمن)
   - هل بيانات حساسة (كلمة مرور، رقم هوية) تظهر في أي Response أو Log بالخطأ؟
   - هل Audit Log يُسجَّل فعلياً لهذه العملية؟
3. صنّف كل ثغرة محتملة: Vulnerability / Attack Vector / Impact / Likelihood / Mitigation.
4. أضف Security Test يغطي كل ثغرة اكتُشفت (مثال: طلب بدون Token يجب أن يُرفض 401).

## Rules
لا تعتبر Feature "مكتملة" في Definition of Done دون اجتياز هذه المراجعة وتوثيق نتيجتها.

## Expected Output
قائمة ثغرات محتملة (إن وُجدت) + إصلاحها فعلياً + Security Tests جديدة + توثيق مختصر ضمن PR/Commit.
